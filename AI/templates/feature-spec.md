# Feature Specification Template

## 1. Purpose

What problem does this feature solve?

## 2. Users and roles

Who uses it? Who can view, create, update, approve, reject, archive, export, or administer it?

## 3. Scope

What is included?

## 4. Out of scope

What is explicitly excluded?

## 5. Business rules

List precise rules and invariants.

## 6. Status flow

Define allowed states and transitions.

## 7. Validation

Define required fields, formats, ranges, uniqueness, dependencies, and conditional requirements.

## 8. Permissions and access scope

Define role/permission codes, tenant/project scope, and object ownership rules.

## 9. Audit events

List actions that must be audited.

## 10. Notifications and background jobs

Define triggers, recipients, templates, retry behaviour, and timing.

## 11. Database impact

Tables, columns, constraints, indexes, migrations, data migration, and retention.

## 12. API impact

Endpoints, requests, responses, error codes, idempotency, and compatibility.

## 13. UI behaviour

Screens, actions, loading, empty, error, validation, success, responsive, and permission states.

## 14. Edge cases

Concurrency, duplicate submission, partial failure, stale state, cancellation, and retry.

## 15. Acceptance criteria

Write testable conditions.

## 16. Test cases

Happy path, validation, permission, tenant isolation, state conflict, concurrency, and failure recovery.
